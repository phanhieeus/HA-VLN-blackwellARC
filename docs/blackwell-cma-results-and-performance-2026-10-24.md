# HA-VLN 2.0 Blackwell: full validation and bundled performance results

Both original CMA validation runs completed successfully on RTX PRO 6000 Blackwell with Python 3.12.13, PyTorch 2.10.0+cu128 and Habitat-Sim 0.1.7. The original `agent/run.py` evaluator and released checkpoint were used. The evaluator compatibility change converts NumPy values only when exporting JSON.

## Full validation reference

| Split | Episodes | SR | NE | CR | TCR | Wall time |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| val_unseen | 1,839 | 0.124524 | 6.461033 | 0.589995 | 18.967917 | 27m 38s |
| val_seen | 778 | 0.158098 | 6.149727 | 0.562982 | 12.781491 | 29m 21s |

README reference values are unseen SR 0.114, NE 6.502, CR 0.689, TCR 22.352 and seen SR 0.165, NE 6.230, CR 0.638, TCR 13.271. The researcher accepts run-to-run variability. These measured Blackwell values are retained as the reference for subsequent work; they are not asserted to match the paper bit for bit.

The runs used four environments, all available episodes, original image resolutions and the original human update schedule. Both returned status 0 and produced parseable aggregate JSON. Raw metrics and the runtime manifest are preserved under `benchmarks/blackwell-cma-2026-10-24/` in the fork and `reproduction-artifacts/results/blackwell-cma-2026-10-24/` locally. Detailed logs and per-episode info were snapshotted privately as `reference-results.tar.gz.bin`.

Use the `SR` field rather than ordinary navigation `success` when comparing these tables. Upstream `HASimulator/metric.py` defines episode TCR as collisions above the episode's collision reference, CR as whether that excess is nonzero, and SR as goal success with zero excess collisions. The evaluator averages those episode values.

## Measured optimization bundle

The bundle combines scene-specific template registration, eight parallel environments, reuse of existing navmeshes and `torch.inference_mode()` around evaluation. It keeps the checkpoint, tensor precision settings, sensor resolutions, 120 human frames, maximum episode steps, simulator version and metric formulas unchanged.

One paired measurement used the exact same 128 episode IDs from eight unseen scenes. Both profiles started from separate hardlinked copies of the same reference navmesh directory, so new files generated by the first profile could not warm the second profile's directory. The original evaluator ran both profiles to completion. This measures the combined bundle; it does not attribute gains to individual changes.

| Measurement | Original profile | Optimized bundle |
| --- | ---: | ---: |
| Environments | 4 | 8 |
| Template registration | All 383 motions | Referenced scene motions, with cached exact frame handles |
| Inference mode | Original no-grad path | `torch.inference_mode()` |
| Total seconds | 143.444 | 84.155 |
| Episodes per second | 0.892 | 1.521 |
| Actual agent steps | 23,486 | 20,772 |
| Agent steps per second | 163.730 | 246.831 |
| Mean GPU utilization | 31.83% | 32.96% |
| Peak GPU utilization | 51% | 52% |
| Peak GPU memory | 5,090 MiB | 8,833 MiB |

Measured end-to-end speedup is **1.70x**, or **41.3% less time**. Observed agent-step throughput improved **1.51x**. Episode trajectories and lengths differed between the two runs, so the agent-step figure is included to expose the workload difference. This is a single paired sample, not a universal speed guarantee or an isolated CUDA kernel benchmark.

GPU utilization stayed around one third on average. The bundle improves throughput while CPU simulation, asset loading and synchronization still leave GPU idle periods. No artificial GPU work was added to inflate utilization.

Original human animation uses a background `time.sleep(0.1)` signal loop. Faster runtime or different environment batching can therefore change human frames relative to policy actions. Preserve this source behavior and record runtime settings when comparing metrics. On this 128-episode sample, reference SR was 0.09375 and optimized SR was 0.125; these sample metrics are not full-split results or evidence of an improved policy.

## Correctness checks

- Native Habitat-Sim template manager verified all 120 exact frame paths for two motion sequences, 240 handles total. Repeated requests reused the same handles without registering more templates.
- The optimized registration rejects missing, duplicate or unexpected frame names instead of silently dropping frames.
- Both original and optimized 128-episode evaluator runs exited successfully and wrote results.
- NumPy JSON conversion was tested using the actual helper extracted from source in an empty namespace.
- Original navmesh generation, collision calculations, human transforms, physics calls and signal timing were not edited by the bundle.

## Run the optimized profile

After restoring the prepared environment and data, run from the repository root:

```bash
export TORCH_HOME=/kaggle/working/havln-cma-cache/torch-cache
export HAVLN_TEMPLATE_SCOPE=scene
export HAVLN_FAST_INFERENCE=1
bash scripts/run_blackwell_cma.sh \
  --exp-config config/cma_pm_da_aug_tune.yaml --run-type eval \
  MODEL.DEPTH_ENCODER.ddppo_checkpoint NONE VIDEO_OPTION "[]" \
  NUM_ENVIRONMENTS 8
```

Append `EVAL.SPLIT val_seen` for seen validation. In the original currently prepared session, use `TORCH_HOME=/kaggle/working/havln-runtime/torch-cache` instead. Environment switches default to original behavior when unset. Unseen has 11 scenes; the current upstream partitioner rejects more environments than available scenes. Seen has 53 scenes.
